# 意图识别与对话管理

> 先把"这个"这类半截话补成完整问题，再让 LLM 读整段对话判断"想干嘛"，最后按"识别要细、处理要合"送上正确的轨道。

## 背景与问题

用户冒出「这个能退吗」，系统要同时想清两件事：**「这个」指哪件商品**（指代消解），**这句话想干嘛**（意图识别）。前者判错检索找错条目，后者判错流程走岔道。

## 设计

### 指代消解 + Query 改写/扩写

```text
「这个能退吗」 --指代消解(求准)--> 「蓝牙耳机还能申请退货吗」
             --Query扩写(求全)--> 3 条变体一起检索 → 结果去重合并
```

- 指代消解是 Query 改写的一种（求准），专门对付"它/这个/那个"；扩写求全。
- 边界：问题本身已完整就别强行改写，否则引入对话历史不存在的信息。

### 意图识别

- **三条路线取舍**：关键词穷举不完；BERT 快准省但应付不了"物流→退款→又回物流"的**意图漂移**；LLM 零样本 + 读整段历史，最终选 LLM。
- **Prompt 四件事**：枚举做选择题、强制 JSON、few-shot 边界样例、留兜底类"其他"。
- **先求准再求省**：初期大模型做准；跑稳后小模型置信度升级，或降级到便宜模型。

### 分流路由（识别要细、处理要合）

```python
def route_by_intent(state):
    if intent == "投诉": return "escalate"
    if intent in ("闲聊", "其他"): return "fallback_script"
    if intent == "商品咨询": return "knowledge"
    if intent in ("退款退货", "售后"): return "refund_flow"
    return "business"
```

| 出口            | 哪些意图       | 守的规矩                           |
| --------------- | -------------- | ---------------------------------- |
| knowledge       | 商品咨询       | 强制检索 → 置信度闸 → Agent      |
| refund_flow     | 退款退货/售后  | 取订单 → 检索政策 → 只判能不能退 |
| business        | 物流/订单/人工 | Agent 自己调工具                   |
| fallback_script | 闲聊/其他      | 固定话术，不进 Agent               |
| escalate        | 投诉           | 安抚 + 转人工，不让模型接手        |

## 关键结论与坑

- **扩写有成本、只对核心场景做**：退款退货/售后这类高频容错低的才扩；"客服电话是多少"直接查。
- **缺信息不问在意图识别站**：意图识别只答"想干嘛"；追问槽位（订单号/退款原因）在执行阶段由 Agent 弹选择器/下拉框回填，靠 `interrupt` 停等。
- **识别要细、处理要合**：九类标签给日志统计/按意图算成本，五条路由给处理，映射表只有一份。
