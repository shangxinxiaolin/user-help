# RAG 混合检索与重排

> 把知识外挂进系统，解决两件事：关键词查表漏召回、向量检索认不准"一字不差"的型号编号。

## 背景与问题

知识库躺着两份规格文档（BE200 与 BE100），八成字句一样、只有型号不同。向量检索看"整段话的意思"，型号编号这种没语义的东西排不上号，上一代的参数表反而排到前面，回答里就把快充功率报错了。

## 设计（三阶段流水线）

```text
Query 理解（改写求准 / 扩写求全 / HyDE）
  ↓
召回：dense 向量 + BM25 各 50 条，同库并存
  ↓
融合/粗排：RRF（k=60）或分数级加权
  ↓
精排：Cross-Encoder reranker，小候选池上重排
  ↓
生成闸：铁律 prompt + 溯源 [1][2] + useful 拒答
```

- **BM25 路径**：关键词打分（命中多、词稀有分高；词频饱和 + 长度归一化两处修正），认"字面"不认"语义"。
- **召回融合**：向量给余弦相似度（[-1,1]）、BM25 给另一个量纲，直接相加没道理——用 **RRF 倒数排名融合**绕开量纲问题。
- **精排**：召回负责"找得全"、精排负责"排得准"；Cross-Encoder 把 query 和文档拼一起读深层语义，Bi-Encoder（BGE-M3 那套）只各查各的。

## 选型理由

| 选型 | 理由 |
|---|---|
| BGE-M3 | 私有化部署、可领域微调、中英双强 |
| Milvus（2.5+） | 一库扛 dense + BM25 两条路径、原生 RRF 融合，省掉另起 Elasticsearch 集群 |
| bge-reranker-v2-m3 | 与 BGE-M3 同底座，Cross-Encoder 精排，中英文榜单稳 |

## 关键结论与坑

- **BM25 在标准化术语上可能反超向量**：型号、优惠券、SKU 这类字面精确的内容，别迷信向量一定强，看 query 特征。
- **混合 RRF 不是"多一路信号总更稳"**：口语/跨文档类问题上，BM25 的噪声会把向量已排对的答案往后挤；真正救回来的是精排。
- **候选池大小 = 召回率上限**：正确文档没进候选池，精排再准也救不回。
- **扩召回别在入库侧做**：入库把一条知识拆成多个问法会占满 Top-K 名额；应放检索侧 Query 扩写，库中每条只存一份。
- **生成闸**：靠 prompt 约束不够，还要 `useful=false` 拒答 + 转人工，挡幻觉。

## SPEC 落点

- 混合检索四策略对比：SPEC 1.5.4（vector / bm25 / hybrid / hybrid_rerank）。
- 证据置信度闸：SPEC 1.5.1（`evidence_confidence`）。
