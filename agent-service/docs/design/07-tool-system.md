# 工具系统与 MCP

> 把写死在代码里的工具，换成一套"注册一下就能用、不动核心代码"的即插即用工具生态。

## 背景与问题

第二章写死的那五个工具（查订单、查物流、查商品）真到生产远远不够：要接物流系统、仓储系统、第三方查询，每接一个都得改代码、重启服务。

## 设计

- **内置工具**：`@tool` 注册在 `app/tools/`，直接写死在代码里，够跑课程演示。
- **外部工具走 MCP**：用标准协议接外部系统，新工具注册即用、不动核心代码。
- **工具执行引擎 + 审计**：所有工具调用记录参数、结果摘要、耗时、重试（`ToolAuditLog`）。

```text
main_agent ⇄ agent_tools
              ├─ builtin（@tool 内置）
              └─ mcp（外部动态工具，独立进程）
```

## 选型理由

- **MCP 解决"即插即用"**：真实客服要接大量外部系统，标准协议让新工具注册一下就能用，不用每次改核心代码、重启服务。
- **边界：MCP 不与 Java 核心业务重复**：订单/物流/退款等核心业务能力走 Java gRPC，MCP 限定为外部动态工具，避免同一业务能力两套实现。

## 关键结论与坑

- **工具描述含糊会导致 Agent 打转**：两个工具用途重叠，模型看完结果一转身又调同一个——`max_turns` 兜底，但根子在工具描述写清边界。
- **工具只收业务参数，身份不靠模型填**：可信身份由服务端上下文注入，工具调用参数里不允许模型填 `user_id`。
